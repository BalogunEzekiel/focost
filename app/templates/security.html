Security & Responsible Disclosure

FOCOST Security

FOCOST applies security controls designed to protect account access, financial records, payment references, AI interactions and administrative functions.

Account security

Password hashing, email verification, password-reset tokens, authentication throttling, secure sessions, CSRF protection and session invalidation controls are used to reduce common account-compromise risks.

Access control

Role-based permissions, least-privilege administration, audit logging and protected administrative routes are used for privileged operations.

Financial and payment security

FOCOST is designed to minimise payment-card data exposure. Payment processing uses the configured payment provider and server-side verification rather than trusting a browser redirect alone.

Data protection

Security headers, environment-managed secrets, controlled migrations, audit trails and data export/deletion controls form part of the platform's security and governance model.

Responsible disclosure

If you believe you have identified a security vulnerability in FOCOST, report it promptly to {{ config.FOCOST_SECURITY_EMAIL }}.

  • Provide enough technical detail to reproduce the issue.
  • Include the affected URL, feature or component and relevant timestamps where available.
  • Do not include passwords, API keys, payment-card details or unnecessary personal data.
  • Do not intentionally access, alter, delete or disclose another person's data.
  • Allow FOCOST reasonable time to investigate and remediate before public disclosure.

For security reporting, the machine-readable security contact is published at /.well-known/security.txt.

Important: No internet-connected service can guarantee absolute security. Security controls are continuously reviewed and improved as FOCOST evolves.
